# 🏆 랭킹을 진짜 데이터로 연결하기 (프론트 작업 — 팀원용)

> 프로젝트 처음이어도 괜찮아요. 아래 순서대로 **복사·붙여넣기 + 한 줄 수정**만 하면 됩니다.

## 이게 무슨 작업인가요?
지금 **랭킹 화면**은 코드에 박아둔 **가짜 데이터**(성수·을지로·익선동…)를 보여줘요.
이걸 **Supabase의 진짜 데이터**(실제 좋아요·레퍼런스 수)로 바꾸는 작업이에요.

이 앱은 화면마다 **"서비스(service) 한 줄만 바꾸면 가짜↔진짜 전환"** 되는 구조예요.
스팟·레퍼런스는 이미 그렇게 연결돼 있고, **랭킹만 아직 가짜**예요. 그거 하나만 바꾸면 됩니다.

## 미리 준비 (한 번만)
1. 터미널에서 최신 코드 받기:
   ```bash
   git checkout integration
   git pull
   ```
2. 백엔드(랭킹 계산 함수)는 **이미 준비돼 있어요** (`ranking_entries` RPC). 팀원은 **프론트만** 하면 돼요.

---

## STEP 1. 새 파일 만들기
`src/repositories/supabase/` 폴더에 **`rankingRepository.ts`** 파일을 새로 만들고, 아래를 **통째로 붙여넣기**:

```ts
import type { RankingRepository } from '../types'
import type { RankingEntry } from '@/types'
import { supabase } from '@/lib/supabase'

// DB 함수(ranking_entries)가 돌려주는 한 줄의 모양 (snake_case)
interface RankingRow {
  spot_id: string
  name: string
  address: string
  image_url: string
  latitude: number
  longitude: number
  tags: string[] | null
  recommended_time: string | null
  created_at: string
  reference_count: number
  total_likes: number
}

export const supabaseRankingRepository: RankingRepository = {
  async getEntries(tab) {
    // 백엔드 랭킹 함수 호출 (tab: 'top10' | 'rising' | 'new')
    const { data, error } = await supabase.rpc('ranking_entries', { tab })
    if (error) throw error

    // DB(snake_case) → 화면 타입(camelCase)로 변환 + 순위 매기기
    return (data as RankingRow[]).map((row, i): RankingEntry => ({
      rank: i + 1,
      spot: {
        id: row.spot_id,
        name: row.name,
        address: row.address,
        imageUrl: row.image_url,
        latitude: row.latitude,
        longitude: row.longitude,
        tags: row.tags ?? [],
        recommendedTime: row.recommended_time ?? undefined,
        referenceCount: row.reference_count,
        createdAt: row.created_at,
      },
      tags: row.tags ?? [],
      likeCount: Number(row.total_likes),
      referenceCount: row.reference_count,
    }))
  },
}
```

## STEP 2. 서비스 한 줄 바꾸기
`src/services/ranking.ts` 파일을 열어서 **mock → supabase 로** 교체:

**바꾸기 전:**
```ts
import { mockRankingRepository } from '@/repositories/mock'
import type { RankingRepository } from '@/repositories/types'

export const rankingService: RankingRepository = mockRankingRepository
```

**바꾼 후:**
```ts
import { supabaseRankingRepository } from '@/repositories/supabase/rankingRepository'
import type { RankingRepository } from '@/repositories/types'

export const rankingService: RankingRepository = supabaseRankingRepository
```
> 딱 2줄이에요: import 줄 하나, 마지막 export 줄 하나.

## STEP 3. 로컬에서 확인
```bash
npm run dev
```
→ 브라우저 `http://localhost:5173` → **랭킹 탭** 확인.
- 이제 **진짜 업로드된 스팟**이 좋아요/레퍼런스 순으로 나와요.
- **주의:** DB에 실제 데이터가 없으면 랭킹이 **비어있어요**(정상). 발견/업로드로 사진 몇 개 올리면 순위가 생겨요.
- TOP 10 / 급상승 / 신규 탭도 각각 다른 순서로 나오면 성공.

## 막히면 체크
- **"ranking_entries 함수 없음" 에러** → 백엔드 담당이 `docs/supabase-ranking.sql`을 Supabase에 아직 안 돌린 거예요. 요청하세요.
- **화면이 비어있음** → DB에 스팟/레퍼런스가 없어서예요. 업로드로 데이터를 넣어보세요.
- **빨간 줄(타입 에러)** → 파일 경로/철자 확인 (`src/repositories/supabase/rankingRepository.ts` 정확히).
- 그래도 안 되면 터미널 에러나 브라우저 F12 콘솔을 캡처해서 공유해주세요.

## 왜 이렇게 하나요? (개념)
```
화면(RankingPage) → useRanking(훅) → rankingService → repository
                                         (이 줄만 바꿈)   mock → supabase
```
화면 코드는 하나도 안 건드려요. **"어디서 데이터를 가져오는지"만** 바꾸는 거예요.
스팟·레퍼런스·저장 기능도 전부 이 방식으로 연결돼 있으니, 다른 mock 화면도 같은 패턴으로 바꿀 수 있어요.
